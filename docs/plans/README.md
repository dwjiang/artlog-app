# Implementation plans — Art Identifier (artlog)

Generated by the `improve` skill on 2026-09-08 at commit `86571a3` from the design document
`docs/design/art-identifier.md` (the proposal for the Nebius × NVIDIA Global AI Hackathon,
deadline 2026-10-30 10:00 PDT). Each step plan is self-contained: an executor with no other
context can run it from the file plus the repo. Execute in the order below unless the
dependency graph says otherwise. Each executor: read the plan fully before starting, honor
its STOP conditions, run its done criteria, and update your row here when done.

Layout: `docs/plans/<workstream>/<step>.md`. Numbers are `<workstream>.<step>` (e.g. 04.03).
Spikes (workstream 00) produce decision records under `docs/decisions/`; build steps produce
code.

## How to run a plan

1. Open the step file; run its drift check; read "Current state" and "Scope".
2. Follow the steps; every step ends with a command and an expected result.
3. Stop on any STOP condition and report; do not improvise around it.
4. Tick the done criteria; set the row below to DONE (or BLOCKED with a one-line reason).

Shared verification commands (established by plan 01.01): `npx tsc --noEmit`, `npm run lint`,
`npm run test:app` (Jest, `src/` + `modules/`), `npm run test:convex` (Vitest + convex-test,
`convex/`), `cd jobs && uv run pytest -q` (Python jobs), `npx convex dev --once` (backend push).

Practical notes:

- **Three independent tracks** after wave 3: *backend* (04.x), *index build* (02.x), *on-device* (03.x). They meet at 04.03 ↔ 03.01 (the identify contract) and at 04.05 ↔ 02.06/03.05 (the venue queue). A single executor should follow the table order; three executors should each own a track.
- **Contract-first starts**: 03.01, 03.06, 05.02–05.05 can be *started* against the API shapes written in 04.03/04.07/04.09 before those land, and integrated afterwards; their listed dependencies say when they can be *finished*.
- **Spikes first**: 00.01 (model export) and 00.06 (native stack) are the two that can invalidate the most downstream work; 00.04 (Token Factory vision model) changes what the README can claim. Start all three in the first days.
- **Critical path** (longest chain): 01.01 → 01.02 → 01.03 → 04.04 → 04.03 → 03.01 → 03.02 → 05.01 → 05.02 → 05.03 → 05.06 → 06.01 → 06.02 (13 steps). Everything else has slack.

## Dependency notes

- 01.03 is the data-model contract; every backend, jobs and on-device plan names its fields. Change it deliberately and grep `docs/plans/` for the field.
- 04.04 precedes 04.03 because every public function goes through `requireDevice` and the rate limiter; the App Attest client side (03.07) is only needed for shared-state writes and can trail.
- 04.01/04.02 are pure libraries; 00.03 measures 04.01 inside a real Convex action and may trigger a WASM path.
- 02.01 owns the Python ↔ Convex ingest contract (`convex/ingest.ts`); 02.02–02.09 only add job modules.
- 02.06 (crawler worker) needs the Convex queue functions from 04.05; 02.07 (enrichment) shares its validator and write mutation with 04.09.
- 03.05 needs the bundled venue asset from 02.02 and `startVisit` from 04.05.
- 05.01–05.05 are UI over behavior that exists; 05.06 and 04.11 are P2 (MVP scope per design §3, but nothing depends on them).
- 06.01 spends EAS builds and touches App Store Connect: run only on explicit request (AGENTS.md).

## Decisions made while planning (not re-audit these)

- **Embedding dimension is 1536, input 512** (C-RADIOv3-B DINOv2-adaptor summary). The design's 768 was never available: the backbone summary is 2304. Storage math in design §5.7 doubles; plan 00.02 measures it.
- **No NVIDIA vision-language model is on Token Factory public endpoints** as of 2026-09-08 (Nano Omni deprecated 2026-08-31; Nano 2 VL retired 2026-04-13). Spike 00.04 chooses the label-reading model and the honest README wording; the text models (Nemotron 3 Super, Nemotron 3.5 Lightning) still satisfy the hackathon's NVIDIA-model requirement together with C-RADIO.
- **VisionCamera is v5** (Nitro-based, `useFrameOutput`, separate barcode package); rectangle detection is a custom Nitro hybrid object (03.02). Spike 00.06 confirms RN 0.86 compatibility.
- **App Attest uses Expo's official `@expo/app-integrity`** — no custom native module (03.07).
- **`huggan/wikiart` is dropped** (license unknown / non-commercial; no identity fields).
- **Convex-test supports vector search** (brute-force), so identify is fully unit-testable.
- **Job launching** is decided by spike 00.08 (GitHub Actions `workflow_dispatch` vs Nebius REST from Convex); plans 02.01/04.05 implement behind one function.
- Rejected: geofences/background location (design), Qdrant unless 00.02 fails, server-side re-embedding before promotion (design §3 deferred), dark mode (AGENTS.md), Android/web (AGENTS.md).
