01

Overview

Artlog identifies a painting by visual retrieval, not by asking a language model what it sees. The phone crops the painting, embeds it with NVIDIA C-RADIOv3-B on the Neural Engine and extracts ORB keypoints. One Convex action searches a versioned vector index, verifies the best candidates with ORB matching and a RANSAC homography, and a trained logistic-regression calibrator decides confident, soft or miss. Everything a visitor does afterwards (reading the wall label, searching the museum's own site, saving, sharing a work into the shared index) runs through the same backend and is gated by device identity, rate limits and daily spend caps. Nothing idles: the request path is the phone and Convex; providers are called live per request; index building runs on a Mac and exits.

Model version c-radiov3-b-int8-512-dinov2-v1: 512 px letterboxed input, 1,536-d output, int8 weights, fp16 compute, ≤500 ORB keypoints (shared/model/model-version.json). The same fake-quantized weights build the index so phone and index share numerics; a drift check against 200 committed iPhone embeddings gates index builds. Calibration URLs live in shared/model/calibration/urls.txt; image hashes and reference embeddings live in jobs/calibration/. App builds validate the bundled model with npm run model:check.

02

System map

Four places where code runs. Only the first two are on the request path; the third is called from Convex per request; the fourth runs batch jobs to completion and exits.

iPhone · Expo SDK 57 dev client

iOS 17+, light mode only, bundle app.artlog.ios. Expo Router with native tabs: Scan, Collection, Settings.
  • Native modules: modules/vision-rect (Nitro: live Vision rectangles at stride 3, still-image rectangle + subject lift, perspective warp, letterbox), modules/coreml-embed (C-RADIOv3-B on the Neural Engine, ~67 ms/crop on iPhone 16 Pro), modules/poi-search (MapKit nearby museums), react-native-fast-opencv (ORB, blur/glare triage), VisionCamera 5 (frames, photos, QR).
  • Local store: expo-sqlite + Drizzle under src/db/ (visits, savedWorks, notes, pendingScans, settings); photos and crops in the app's document directory; bundled assets/venues.db (42,452 venues) refreshed from Convex file storage.
  • Identity: Convex Auth anonymous session from a 256-bit secret in SecureStore; one App Attest key per install signs every shared write.
  • Always-on workers mounted in src/app/_layout.tsx: DeviceIdentity, QueueFlusher, CollectionSync, VenueResolver, embedder warm-up.

Convex · the whole request path

dev usable-owl-256 · prod admired-goldfinch-660. Pure libraries under convex/lib/; ORB algorithms shared with the phone via shared/orb/. Calibrator inference stays in Convex; Python/TypeScript parity fixtures live in shared/calibrator/.
  • Public surface (36 functions): identify; label flow (fetchQr, readLabel, verifyLabel); museum-site search; contributions; feedback; collections, sync, visits; devices, accounts; venue confirmation; the live scans.get subscription; venueTable.latest; health.ping.
  • Internal (99): docent and "Right now" generation, the promotion cron, revert cascades, placement review, checklists, ingest and export for the Python jobs, review queues.
  • Data: 25 tables; one vector index (vectors.by_vector, 1,536-d, filtered by modelVersion); file storage for ORB descriptor files, private collection photos, shared crops and the venue table.
  • Controls: @convex-dev/rate-limiter per device, atomic daily spend reservations, three feature flags, App Attest verification (a Node action for attestation, WebCrypto for assertions).

Providers · called live, per request

Provider keys live in Convex environment variables and the operator’s job environment. The phone never calls a model provider.
  • Nebius Token Factory (OpenAI-compatible, strict json_schema, thinking off): Moonshot Kimi K2.6 reads labels and describes crops; NVIDIA Nemotron 3 Super writes fact sheets; Nemotron 3.5 Lightning writes docent prose, extracts matched exhibition-image captions and moderates text.
  • Tavily search: museum-site search, label verification, fact-sheet research, "Right now". One credit per search, reserved atomically against a daily cap.
  • Museum websites: bounded page fetches per visitor request (a matched exhibition page or up to 3 description-search object pages), only on the venue’s own hosts, identified User-Agent, opt-out registry checked first; extracted identity fields and evidence URLs can be stored, fetched page HTML is not.
  • Wikidata and Wikipedia: title/artist pair checks, artist lifespans, fact-sheet sources. Apple: App Attest, Sign in with Apple JWKS.

Operator Mac · Python jobs

Apple M5 Pro, uv, torch on MPS fp16. jobs/artlog_jobs/. No scheduler, no cloud job: every command runs to completion and exits.
  • Index build: seed venues → fetch Met / AIC / Wikidata metadata → download, drift-check, embed and extract ORB per shard → dedupe → push to Convex through the admin deploy key.
  • Enrichment: enrich.run writes fact sheets and docent prose in batches under the same spend caps.
  • Calibrator: augment, sample, train → a JSON artifact a human pastes into convex/lib/calibrator/weights.ts.
  • Model asset: scripts/model/ exports and compiles the CoreML model. The compiled files are committed with Git LFS; npm run model:check validates them before iOS builds and EAS dependency installation.
  • Operations: npx convex run for review queues, placement decisions and manual promotion.
03

User journey

Each step pairs what the visitor sees with what the system does at that moment. The happy path is steps 1–4 and 8; steps 5–7 are the routes taken when the index does not know the painting; steps 9–12 are the rest of the app.

Open the app: no account, straight to the camera

launch, ≈4 s until the model is warm

Visitor sees

  • The Scan tab with a live viewfinder; a venue pill top-left that reads "Locating…", then the museum's name.
  • When two seeded venues are within 400 m, or none, a "Looks like you're at…" sheet with nearby options.
  • A queue badge top-right if scans are still waiting for signal.

System does

  • DatabaseGate waits for src/db/use-database-migrations.ts to apply the bundled SQL in src/db/migrations/ before rendering database consumers; the embedder starts loading the CoreML model.
  • DeviceIdentity signs in anonymously (a random 256-bit secret in SecureStore; only its SHA-256 is stored), calls devices.registerDevice (trust weight 0.5), then generates an App Attest key, takes a challenge and calls devices.attestDevice, which verifies the attestation in a Node action. Retries back off to 30 s; a rejected key is replaced once.
  • VenueResolver restores an open visit, takes one Balanced location fix and queries the bundled venue table: one venue within 150 m and nothing else within 400 m resolves automatically; two or more within 400 m open the chooser; none triggers a MapKit search within 300 m. The GPS fix is not sent to Convex; the MapKit fallback uses a location-based Apple search. A local visit starts and visits.startVisit mirrors it (a visit resumes if the same venue within 4 h).
  • Confirming a MapKit place sends its name, coordinates and website with an App Attest assertion to museums.confirmPoiVenue, which dedupes within 100 m, inserts a poi venue and schedules a probe of its website for a collection section.
  • Once a day the app asks venueTable.latest and stages a newer venue table for the next launch.
Code: src/app/_layout.tsx, src/components/database-gate.tsx, src/db/use-database-migrations.ts, src/lib/device-identity.ts, src/lib/venue/use-venue.ts, src/lib/venue/resolve.ts, src/lib/venue/refresh.ts, convex/auth.ts, convex/devices.ts, convex/museums.ts

Frame the painting and capture

live guidance at ≈10 detections/s

Visitor sees

  • An animated outline around the painting and one line of guidance ("Move closer", "Straighten up", "Ready" with a light haptic). The shutter is always available.
  • Alternatively an Import button for a photo already taken.
  • "Processing photo…" for about a second, then the result card. A blurry or glary shot gets a one-line retake banner instead ("Hold steady and try again", "Dodge the glare").

System does

  • VisionCamera streams 4:3 frames; every third frame goes to Vision rectangle detection in the native module; a tracker turns the observations into a stable quad and guidance.
  • On the shutter: capture a JPEG, resolve the venue context (waiting at most 3 s for a fresh fix), then run the capture pipeline: still-image rectangle detection plus Vision subject lifting → pick the quad → perspective warp → resize to 512 px and letterbox with the image-mean color (the same function the index build uses) → triage on a 256 px gray copy (Laplacian variance below 60 is blur; more than 4% blown pixels is glare) → CoreML embedding (1,536 floats) → ORB (≤500 keypoints, 32-byte descriptors).
  • The photo, crop, vector and features are written to pendingScans before any network call. Online, identify is called inline; offline, the row stays queued.
  • Library imports read EXIF time and GPS; the photo's own position names the venue and no visit starts.
Code: src/components/scan/scan-screen.tsx, src/lib/capture/use-rect-detector.ts, src/lib/capture/pipeline.ts, src/lib/capture/default-stages.ts, src/lib/capture/triage.ts, modules/vision-rect/, modules/coreml-embed/, src/lib/orb/extract.ts

Identify: one Convex action

≈1.65 s median, camera to card, on iPhone 16 Pro

Visitor sees

  • Nothing yet: the card opens with "Identifying…" over the crop.

System does

  • Vector search (top 32, filtered to the phone's model version) → collapse to 20 physical objects → ORB verification of the first 10 with stored descriptors → calibrator → confident, soft or miss. Written to the scan document; section 04 walks through every step.
  • A confident result schedules two follow-ups the card never waits for: docent prose and "Right now".
Code: convex/identify.ts, convex/lib/identifyPipeline.ts, shared/orb/, convex/lib/calibrator/, convex/scans.ts

Read the result card

live document; prose arrives within seconds

Visitor sees

  • Confident: the crop with the artwork's corners drawn from the homography, a thumbnail, title / artist / date / medium / institution, a save bar, "About this work" (three or four cited sentences with source chips; a pending state on the first ever identification of that work), and "Right now" when enabled.
  • Soft: the best guess, editable, with "Maybe one of these?" runner-ups. Miss: blank editable fields; the low-probability best stays among the suggestions rather than being named.
  • "Not right?" opens a sheet with the runner-ups and the label button; below a non-confident card sits "Get the exact answer — point at the label".

System does

  • The card subscribes to scans.get; docent sentences, the fact sheet, "Right now", label-flow and museum-search state all arrive through that one document. The local row is marked reviewed.
  • Thumbnails: a contributor's shared crop from file storage, else a hotlinked source image, only for public-domain works.
  • "Not right?" signs a rejection with App Attest and calls feedback.rejectMatch (3 per work per day per device): the scan's vector and candidate signals become a labeled hard negative; at 20+ rejections and a 30% reject ratio the object is flagged and gets a 0.2 rejection penalty (capped at 0.8). The current lr-v2 coefficient for this signal is zero, so the recorded penalty does not change its score.
  • Picking a runner-up resolves the rejection and, when the visitor's venue disagrees with the object's placement, files a placement proposal. Reading the label resolves it with the contribution; a label naming the rejected work undoes the rejection.
Code: src/components/scan/result-screen.tsx, src/lib/result/state.ts, src/lib/result/feedback.ts, convex/feedback.ts, convex/lib/rejectionPenalty.ts, convex/placements.ts

Not in the index: search the museum's own site

with one-time consent; ≤2 Tavily credits per attempt

Visitor sees

  • A consent sheet the first time ("send a crop of the painting to the museum-site search"); revocable in Settings → Privacy.
  • Stage chips on the soft card: exhibitions → check → describe → search → check.
  • Either "Found on the museum's site: Title, Artist" with the page link and locked fields, or "Not on the museum's site — point at the label".

System does

  • Exhibitions first. museumSearch.searchExhibitions spends one credit on "<venue> current exhibitions" scoped to the venue's hosts and returns up to 3 pages with up to 6 images each. The phone downloads each image, letterboxes and embeds it, and keeps a candidate only when cosine ≥ 0.85 and an ORB homography holds ("text proposes, pixels decide"). confirmSearchCandidate then fetches the exhibition page and names the matched image from structured metadata, or asks the configured DOCENT_MODEL (recorded as Lightning) to extract the title and artist verbatim from the matched image’s caption; a page that cannot name the image is a terminal identity unresolved.
  • Then description search. searchMuseumSite sends the crop to Kimi for a description and artist guess (never stored or logged), runs one Tavily search on the venue's hosts, fetches at most 3 object pages and extracts title, artist, accession and the page image; the phone runs the same image check; a match is confirmed with tavily+image evidence after moderation.
  • Guards: feature flag, venue must have a website and not be opted out, 20 attempts/h per device, both provider caps reserved in one transaction, a revision counter so a stale search cannot overwrite a newer confirmation.
Code: src/lib/museum-search/flow.ts, src/lib/museum-search/candidate-check.ts, src/lib/label/image-check.ts, convex/museumSearch.ts, convex/lib/exhibitionSearch.ts, convex/lib/exhibitionIdentity.ts, convex/lib/describePrompt.ts

Read the wall label

QR is instant; a photo read is one Kimi call

Visitor sees

  • A label viewfinder ("Not in our index yet — point at the label"), QR detection ("Found a QR code"), a shutter and an import button.
  • Progress steps: QR or read → verify → image check. Then a form: verified fields locked with an evidence badge (museum page, QR, Wikidata, museum search, confirmed image), the rest editable; unlocking a field marks it user-edited.
  • Save to collection, automatically sharing eligible confirmed labels and a small artwork crop.

System does

  • QR: label.fetchQr accepts only URLs on the venue's own hosts, fetches the page politely and extracts fields from JSON-LD and meta tags (evidence qr).
  • Photo: the phone downsizes the label photo (≤1.5 MB base64); label.readLabel sends it to Kimi K2.6 with a strict schema (title, artist, dates, medium, accession, credit line, per-field confidence), then moderates the text with Lightning. The photo is not stored or logged.
  • Verify (label.verifyLabel), strongest first: the accession number resolves on the venue's collection site through its accession URL pattern (accession); the title + artist pair exists on Wikidata (wikidata) with artist-lifespan and country plausibility warnings; one museum-scoped Tavily search names the pair (tavily), and a page image the phone confirms upgrades title and artist to tavily+image. Moderation runs on the verified values. Fields with locking evidence are retained across re-verification when unchanged.
  • Offline: the label photo or QR URL is stored beside the pending scan; the queue runs the label flow automatically after identification when the result is not confident.
Code: src/components/scan/label-capture-screen.tsx, src/lib/label/flow.ts, src/lib/label/label-deps.ts, convex/label.ts, convex/lib/labelVerify.ts, convex/lib/labelPrompt.ts, convex/lib/pageExtract.ts, convex/lib/venueFetch.ts, convex/lib/moderation.ts

Share the work into the shared index

automatic on save, no account

Visitor sees

  • A notice before saving explains what is shared with the index: the fingerprint, the verified fields and a small crop of their own photo (≤256 px) that becomes the card thumbnail for the next visitor.
  • A status after sharing: tentative or rejected as a duplicate. A share that fails without a connection waits on the phone and is retried on reconnect or foreground, unless the artwork is deleted first; other failures offer a retry while the artwork remains saved. Contributions are listed in Settings → Contributions, each withdrawable.

System does

  • The phone re-verifies edited fields, resizes the crop to a JPEG ≤200 KB, uploads it to Convex file storage, signs the payload with App Attest and calls contributions.contribute.
  • The action authorizes the write in one transaction (attested, 20/h per device, label flow verified and clear), stores the ORB features as a file, then checks for replays: a vector within 0.995 cosine of an indexed work or of this device's earlier contributions at the venue is rejected as a duplicate. Otherwise a tentative contribution is committed with the verified fields, evidence kinds, source page and any Wikidata ID.
  • Publishing creates or joins a tentative shared entry at the museum.
Code: src/lib/label/contribute.ts, src/lib/label/share-saved-label.ts, convex/contributions.ts, convex/lib/orbStorage.ts, shared/attestation/attested-payloads.ts

Save to the collection

instant, local first

Visitor sees

  • A save bar on every card, including unidentified and queued ones (a title is required). Success haptic, then "View in collection".

System does

  • The fields as displayed or edited become an immutable snapshot row in local SQLite with the photo and crop paths, the visit and gallery. The original stays on the phone; a private JPEG copy (≤2,560 px) and crop (≤512 px) upload to Convex file storage through authenticated /collection-photo requests. Collection rows store their file references.
  • collections.saveToCollection mirrors the row (localId, snapshot, venue, visit, object and artwork pointers) and increments the object's confirm count only when title and artist were left exactly as suggested. A failed mirror stays queued for collection sync.
Code: src/lib/result/save.ts, src/lib/result/snapshot.ts, src/db/repos/saved-works.ts, convex/collections.ts

Browse the collection

works offline

Visitor sees

  • Grid, Canvas and Visits views with search; a saved-work screen with the photo, snapshot fields, a note editor, "About this work" when the artwork has prose, and delete.

System does

Settings

account optional, sync only

Visitor sees

  • Contributions: automatic sharing details and the list of contributions with withdraw. Account: Sign in with Apple, sign out, delete account. Export: the collection as JSON through the share sheet. Privacy: the museum-search consent toggle and the privacy copy. About: version, model version, backend health, source link. Dev builds add capture timings, an App Attest check, the calibration export and an ORB parity check.

System does

No signal

identified when the connection returns

Visitor sees

  • A "waiting for signal" card that still offers the label capture and a save; a queue badge and a queue sheet listing waiting, failed and unreviewed scans with retry and discard.

System does

  • The vector and features were computed at capture time, so the queue row is complete. The flusher runs on launch (after the anonymous session exists), on reconnect and on foreground: oldest first, one run at a time; transient errors pause that task type with exponential backoff up to 60 s and honor Retry-After; other errors count an attempt. A visit is synchronized before its scans are sent.
  • After identification, a queued label photo or QR runs through the label flow when the result is not confident, and is dropped when it is.
Code: src/lib/queue/queue.ts, src/lib/queue/flush.ts, src/db/repos/pending-scans.ts, src/components/scan/states/

Update the app after a model change

client recovery implemented; index rebuild deferred

Visitor sees

  • An "Update the app to identify" card (TestFlight or App Store link); the crop stays on the phone and can still be saved.

System does

  • identify answers unsupported_version for a model version outside SUPPORTED_MODEL_VERSIONS. The queue can re-embed a retained crop locally and resend it when the installed model changes. Each indexed vector has a modelVersion, and retrieval filters on it. A dedicated index re-embedding job is not implemented. For this pre-release app, a future model change replaces the model, index and callers directly; overlapping versions and compatibility migrations are not requirements (docs/todos/deferred-product/README.md).

Identify, step by step

The one action on the request path. Left column: the phone. Right column: Convex. Every server step runs in the default runtime; visual inference already ran on the phone.

iPhone
Convex
1
Capture pipeline produces vector[1536], descriptors and keypoints (ORB wire format), model version, venue and visit IDs, capture time. Persist to pendingScans.
2
Call api.identify.identify (an action) with a localId the phone generated.
Resolve the device from the auth identity; refuse banned devices. Rate limit: token bucket, 60/min, burst 20. Validate the vector (1,536 finite floats) and decode the ORB features. A model version outside SUPPORTED_MODEL_VERSIONS short-circuits to unsupported_version.
3
scans.create: idempotent on (device, localId). An already identified scan is returned as is; a failed or older-model scan restarts with a higher generation. The visit must belong to the device and venue.
4
ctx.vectorSearch('vectors','by_vector'): top 32 by cosine, filtered to the scan's model version. Alternate views of the same painting are separate rows.
5
loadCandidates: follow mergedInto to the surviving object, drop reverted objects, keep the best score per object, rank and cut to 20. Join the artwork, the owner museum, the current placement (gallery, on view) and the descriptor reference (storage id, keypoint count).
6
loadContext: the visit's last confident gallery (valid 15 min) for the gallery feature; banned-device and visit-ownership checks.
7
Load the ORB files of the first 10 candidates that have descriptors from file storage, concurrently (count×32 descriptor bytes then count×16 keypoint bytes).
8
runPipeline: for each verified candidate, Hamming 2-NN matching (ratio 0.8, distance ≤64) and a RANSAC homography (5 px, 1,000 iterations) with winding, area and determinant sanity rules. Signals per candidate: similarity, margin to the runner-up, candidate count, at venue, gallery same/different/unknown, on view, keypoint count, inliers, homography valid, object penalty (hub penalty, currently 0, plus rejection penalty; the lr-v2 weight for this signal is also 0).
9
Calibrator lr-v2: a logistic regression over eleven featurized signals plus two hard rules. Textured works (≥80 keypoints) need ≥15 inliers to be confident; low-texture works need similarity ≥0.93, margin ≥0.04 and venue agreement. Outcome: confident when the top probability clears the threshold and the rules pass, soft when only the probability does, else miss. Runner-ups are the next best objects.
10
scans.setResult (generation-checked): outcome, best (object, artwork, probability, gallery, corners from the homography), runner-ups, per-candidate signals for later feedback, calibrator version. A confident result at the visit's venue updates visits.lastConfidentGallery.
11
Confident only: scheduler.runAfter(0) for docent.ensure and rightNow.fetch. The card never waits on a model call.
12
Record the result on the pending row; navigate to the card; subscribe to scans.get for prose, "Right now" and later state changes.
Return the display document: joined titles and fields, a thumbnail URL (stored crop or public-domain hotlink), the label-flow and museum-search state, never the raw OCR.

Behind the scenes

Work that runs after, beside or independently of the visible action: scheduled Convex functions, the always-on workers in the app, and the Python jobs the operator runs by hand.

iPhone: always-on workers

Mounted once in the root layout under the database gate and the auth provider. None of them blocks the UI; each is a component that renders nothing.

DeviceIdentity

  • Anonymous sign-in with the device secret; then register and attest once per launch.
  • Keeps the challenge and Apple's attestation object across retries; backs off up to 30 s; mints a new key only on a key mismatch or invalid attestation.
  • Simulators register with platform simulator and skip the signature check while attestation is optional on the deployment.
src/lib/device-identity.ts

QueueFlusher

  • Starts once the session exists: re-queues rows interrupted by a process restart, then flushes; flushes again on reconnect and on foreground.
  • Oldest first, one run at a time. Re-embeds a crop locally when the app's model version moved on; resolves the visit before sending; then runs pending label flows.
  • Backoff 2ⁿ s capped at 60 s; transient errors (network, rate limits, Retry-After) pause the task type without counting an attempt.
src/lib/queue/queue.ts, src/lib/queue/flush.ts

CollectionSync

  • Debounced 500 ms after any local collection change, on foreground and on reconnect; retries after 30 s on failure.
  • Scope is the device, or the account plus its linked devices; a scope change re-queues every row. Checkpoint stored in the local settings table.
  • Pushes up to 500 rows per call; pulls sibling devices' copies page by page.
src/lib/account/collection-sync.ts, src/lib/account/sync.ts

VenueResolver

  • Hydrates the open visit, resolves on launch and every foreground, and opens the venue sheet when the reducer asks for a choice.
  • Serializes visit starts and ends to the server so a re-visit cannot resume a visit already ended locally.
  • Checks for a newer venue table at most once a day; a verified download is staged and swapped in on the next launch.
src/lib/venue/use-venue.ts, src/lib/venue/visit-sync.ts, src/lib/venue/refresh.ts

Embedder warm-up

  • Loads the CoreML model at launch and runs one prediction on a black image so the first capture does not pay the load.
  • Fails loudly when the bundled asset is missing or its version differs from shared/model/model-version.json.
src/lib/embed/embedder.ts, modules/coreml-embed/ios/Embedder.swift

Card-side housekeeping

  • Marks a scan reviewed when its card is seen; keeps a label draft per scan so an interrupted share resumes.
  • Museum-search state is restored from the scan document, never by repeating a provider call.
src/db/repos/pending-scans.ts, src/lib/label/draft.ts, src/lib/museum-search/restore.ts

Model delivery and build checks

The compiled model is a repository asset under modules/coreml-embed/ios/Models/. .gitattributes assigns the files inside *.mlmodelc to Git LFS; the readable model-manifest.json stays in ordinary Git. The app bundles the compiled model as a CocoaPods resource.

git lfs install
git lfs pull
npm run model:check

Run from the repository root when preparing an existing checkout. Normal checkouts materialize the model from the LFS cache; worktrees on the same Mac share that cache. model:check rejects missing/empty required files, unresolved LFS pointers, version or dimension mismatches, and a weights SHA-256 that differs from the manifest. It runs as preios and eas-build-pre-install using Node 22.13+. EAS uploads include materialized model files through .easignore; CI must retrieve LFS objects before packaging.

To change the model, export with scripts/model/export_coreml.py, compile with scripts/model/compile-model.sh, and commit the model, manifest and version contract together. Compilation validates a temporary output before replacing the tracked asset. The Python index build uses the matching fakequant_state.pt. Procedures and checks: scripts/model/README.md.

  • Shared writes (contribute, reject, venue confirm, placement proposal, account link) require an App Attest assertion over nonce.payload; the server consumes the challenge, verifies the signature against the device's stored public key and advances the counter.   • Moderation runs on every label read, museum-page candidate and contribution before it reaches a screen or the shared index; a blocklist is the fallback when the model is unavailable.

Data

Three identities matter: an artwork is the work as a concept (one row per Wikidata item or merged record), an object is one physical painting owned by a museum, and a placement says where an object is or was. Vectors and descriptors hang off objects; scans, feedback and contributions hang off devices.

Convex tables by role

The index

  • artworks title, artist, date, rights status, multiplicity, cached fact sheet and docent prose, enrichment claim.
  • objects key (met:…, wikidata:…, user:…), owner, accession, source, page URL, thumbnail (hotlink or stored crop), confirm/reject counts, penalties, mergedInto, provenance, reverted.
  • placements venue, gallery, on view, dates, source (feed, checklist, contribution, proposal, manual), confidence.
  • vectors object, model version, source (corpus, user, user_scan), view key, the 1,536-float embedding under the vector index.
  • descriptors object → ORB file in storage (sha256, keypoint count, input size, extracted from).
  • museums 42k venues with coordinates, website, collection site and platform, accession URL pattern, region, opt-out. museumWorkIdentities maps a venue's accession or page to an artwork. venueTables published SQLite versions. ingestCounters singleton row counts.

Visitor state

  • devices App Attest key and public key, counter, trust weight, banned, account link, platform.
  • accounts Apple user id, email, linked device ids (≤20).
  • attestChallenges single-use nonces (5 min) for attest, assert and Apple sign-in.
  • scans one live document per capture: vector, status, outcome, best and runner-ups with corners, candidate signals, "Right now" card, label-flow and museum-search state, generation.
  • visits and visitStarts venue sessions with the last confident gallery; collections immutable snapshots plus notes and deletions per device.

Shared-index inputs

  • contributions vector, ORB file, shared crop, verified fields with evidence kinds, source page, status (private → pending → promoted, or rejected).
  • feedback rejections with the scan's signals, resolution (unresolved, runner-up, label, false rejection) and multi-view bookkeeping.
  • placementProposals evidence scans and devices, readiness, reviewer decision, promotion record.
  • promotionState the multi-view cursor.

Caches and controls

  • artistContext the "Right now" cache per artist and region with in-flight coalescing.
  • factCorrections flagged facts awaiting review.
  • dailySpend Token Factory calls and Tavily credits per UTC day.
  • optOuts, takedowns rights requests with applied timestamps.
  • Convex Auth tables (users, authAccounts, sessions, refresh tokens) and the rate-limiter component's own tables.
